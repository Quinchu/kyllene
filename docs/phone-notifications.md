# Android posted-notification reader

`phone_notifications` is separately off by default. Turn on Phone tools and Notifications, then grant Kyllene notification listener access in Android settings. This is **not** the permission to post Kyllene's notifications. The user can revoke listener access in Android settings. The listener receives notifications from other apps; it excludes Kyllene's own package and never opens, dismisses, replies to, or invokes notification actions. The result can contain sensitive notification text and is sent to the agent when it calls the tool.

Arguments: optional `after` (nonnegative integer, default 0), `generation` (string from the previous page), and `limit` (integer 1–50, default 20). The response has `generation`, `next`, `overflow`, `has_more`, and `events`. Each event contains `cursor`, `package`, `posted_at_ms`, and available `title`/`text`. It returns posted callbacks, including updates, not a history from before enabling or a snapshot of active notifications. Fields are bounded (package 256, title 1024, text 4096 characters). The last 100 events are kept only in process RAM; older events are dropped. `overflow` indicates that `after` predates dropped events, or exceeds this generation's latest cursor. Pass the returned `generation` with `next` on every subsequent page. On a mismatch the phone starts at cursor 0 in the new generation and sets `overflow`; clients should discard old-generation state. Legacy clients omitting `generation` must detect a changed response generation and refetch from 0 before processing events, since overlapping cursor ranges can otherwise skip events. Pages may contain fewer than `limit` events to stay within the gateway result budget; follow `has_more`.

The queue is cleared when the process observes the tool disabled, listener access revoked, or listener disconnected. Each post and read also checks the current settings, listener access and connection; an unavailable listener returns an error. A process-local revocation counter invalidates the queue on the next observation even if settings changes are conflated. Revocation with no listener callback or subsequent read/post is likewise detected only at the next observation. Process death loses the queue, and Android may delay or omit callbacks, especially while the listener is disconnected; this is not an audit log or guaranteed delivery. Existing notifications are not backfilled after a restart. The generation changes on reset and process restart.

The gateway's separate herald-push plugin must also define and advertise the `phone_notifications` schema, including the optional `generation` string argument, before an agent can invoke it. The plugin version pinned by this repository may not contain that definition; merely enabling the switch does not update that separate component.
